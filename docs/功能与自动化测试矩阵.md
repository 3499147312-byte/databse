# 国康直营管理微信小程序 V1.2 功能与自动化测试矩阵

## 1. 测试方法

本项目采用接近测试驱动开发（TDD）的结构：每项业务能力先定义“前置数据—执行动作—预期结果”，再由自动化测试调用真实业务函数验证。测试使用内存云数据库，不连接正式 CloudBase，不会修改正式账号、库存、销售、费用或回款数据。

测试数据全部匿名化：

- 角色：测试老板、测试审核、测试财务、经理甲/乙、主管甲/乙、代表甲/乙。
- 团队：M001/S001/R001 与 M002/S002/R002 两个相互隔离的团队。
- 主数据：甲/乙区仓库、客户、门店，240片/120片测试产品。
- 业务数据：销售、批号库存、费用、应收、回款、政策、日报、周报和审计日志。
- 边界数据：停用主数据、跨团队数据、过期批号、负数/超额/错误精度、重复请求、错误上下级和有依赖人员。

## 3. 八类批量导入覆盖

| 导入类型 | 测试数据 | 写入结果 |
|---|---|---|
| 人员 | 匿名经理、强临时密码 | 创建账号、密码哈希、强制改密 |
| 仓库 | 甲区仓库、责任经理、30天账期 | 创建仓库并绑定经理 |
| 客户 | 诊所客户、主管和经理 | 创建客户并验证上下级一致 |
| 门店 | 客户、代表、仓库同团队 | 创建门店并复制团队归属 |
| 产品 | 测试产品、规格和换算系数 | 创建产品 |
| 库存 | 入库单、批号、有效期、价格、数量 | 创建库存流水并重建批号余额 |
| 政策 | 价格、返利、推广费、三层提成 | 创建“待老板审核”政策 |
| 历史销售 | 销售单、产品行、批号、价格和提成快照 | 创建已通过历史销售，重建库存和应收 |

代码当前支持人员、仓库、客户、门店、产品、库存、政策、历史销售共 8 个导入数据类型，自动化测试已全部覆盖。

## 4. 底层规则与安全覆盖

- 金额四位小数、正数/非负数、日期、月份、账期、编码和批号格式。
- 多产品销售汇总、经理直管代表的主管提成并入经理提成。
- 标准政策与客户政策、客情额度、应收状态和稳定文档 ID。
- 经理/主管/代表数据隔离，老板全局权限，总部审核只读，总部财务闭环权限。
- 微信登录绑定、账号锁定、强密码、敏感字段过滤。
- 幂等请求：成功复用、处理中拦截、失败状态记录。
- 审计日志字段和详情长度限制。
- CSV BOM、逗号、引号、换行、空行和非法引号。
- API 44 个动作路由、未知动作、业务错误和内部错误脱敏。
- 13 个页面文件完整，页面使用的动作与云函数路由双向一致。
- 动态权限四种调整模式、团队/区域/客户/仓库范围和授权到期。
- 高危权限二次确认、老板审批、收回强制重登和代理审批竞争保护。

## 5. 自动化执行

在项目根目录执行：

```powershell
npm.cmd test
```

或者直接使用 Node：

```powershell
node tests/run-all.js
```

自动化通过只能证明代码规则和内存集成流程正确。上线前仍须按《上线前验收清单》完成微信开发者工具、体验版真机、正式 CloudBase 权限/索引、扫码登录和多人角色验收。
