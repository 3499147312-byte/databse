- 执行日期：2026-07-26
- 测试对象：V1.2动态权限、权限管理员、高危授权和审批代理

## 二、本次补测原因

复核原测试报告后，发现高危申请“通过”已有直接用例，但“驳回”分支只写在报告中；区域范围、普通权限收回、费用主管代理和伪造跨团队请求也缺少完整业务流程证据。本次补齐这些分支，使报告描述与可重复执行的测试保持一致。

## 三、新增流程测试结果

| 用例 | 前置数据与操作步骤 | 预期及实测结果 | 结论 |
|---|---|---|---|
| PERMISSION-REQUEST-REJECT-01 | 老板指定M001为权限管理员；M001为R001申请销售作废权限；老板填写驳回原因 | 1字原因返回`INVALID_REASON`；有效原因后状态为“老板已驳回”；授权不写入；重复处理返回`REQUEST_NOT_PENDING` | 通过 |
| PERMISSION-REVOKE-ORDINARY-01 | R001先正常查看本人销售；老板将`sales.view`设为禁用；R001下一请求再次打开销售页 | 不要求重新登录；下一请求立即返回`PERMISSION_DENIED` | 通过 |
| PERMISSION-REGION-01 | 将M001设为海南、M002设为广东；把R001的销售查看权限替换为“指定区域：广东” | 页面只返回广东团队门店ST002和销售SALE003；海南记录不可见；对海南记录的范围检查返回`SCOPE_DENIED` | 通过 |
| PERMISSION-FORGE-01 | 获得广东区域只读范围的R001伪造请求，尝试向R002门店ST002提交销售 | 动态查看范围不改变组织归属；提交被`STORE_FORBIDDEN`拦截，未生成销售记录 | 通过 |
| PERMISSION-EXPIRY-EXEC-01 | 为R001构造已于2020年到期的临时经营业绩权限并执行权限检查 | 有效权限列表不含该能力；实际执行返回`GRANT_EXPIRED` | 通过 |
| DELEGATION-EXPENSE-SUPERVISOR-01 | 老板设置M001团队费用主管阶段由S002代理；费用EXP001进入待主管审核；S002通过 | 状态变为待经理审核；轨迹记录`delegated=true`、主管阶段和授权编号；第二次处理返回`WRONG_APPROVAL_LEVEL` | 通过 |
| PERMISSION-ROLE-REVOKE-01 | 老板创建含销售作废能力的临时角色并绑定R001，再从模板移除该高危权限 | 高危权限移除后R001被设置`reauthRequired=true`，必须重新认证 | 通过 |

以上补充测试新增24处直接断言或错误码检查。
